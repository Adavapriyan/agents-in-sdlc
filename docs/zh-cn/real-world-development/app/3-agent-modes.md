刚才我们为项目添加了一个小功能，但更大的更改需要更完善的流程。幸运的是，GitHub Copilot app 可以融入组织现有的工作流程，帮助我们以正确的方式构建正确的内容。本课将开启一系列课程，带你体验典型的智能体驱动开发流程：从议题出发生成新功能，确保代码有效、功能符合预期，最后成功合并到项目中。

> [!NOTE]
> 后续功能开发会继续使用同一会话。通常会为不同类型的文件创建不同会话或 PR，但为了让你专注于核心概念，本研讨会采用了简化流程。

本课将学习如何：

- 从 GitHub 议题开始新的智能体会话。
- 在 **Plan** 模式中确定需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续开发此功能时，你还将更新仓库说明、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 智能体并打开功能 PR。

## 场景

Tailspin Toys 的游戏目录不断扩充，访客需要按类别和发行方筛选游戏。待办事项中的议题描述了此功能，但在开始编码前，需要先确定类别组合等细节。你将使用 Plan 模式确定这些决策，再授权 Autopilot 执行范围明确的实现。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则，事实上这些原则变得更加重要！大多数开发人员遵循的流程大致如下：

1. 打开已提交的议题，了解需要完成的任务。
2. 制定实现计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述步骤类似。

遵循这种标准方法，可以确保 AI 生成的代码满足需求，并经历与手写代码相同的审核流程。

## 会话模式

**会话模式**控制智能体的自主程度。可以通过提示框下方的下拉菜单设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。执行计划前，你可以审查并批准。
- **Autopilot**：智能体完全自主工作，编写代码、运行测试并不断迭代，无需等待输入。

先使用 Plan 模式并审查计划，然后使用 Autopilot 实现计划。

## 从议题开始会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 分支已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 仓库文件夹，然后在仓库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已有的预置议题，无需再创建。
2. 选择 **New session**，并基于更新后的 `main` 选择**新工作树**。

    ![GitHub Copilot app 中的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认会话已关联议题，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中可用，但在会话中不可用，请检查 app 的 PATH 或版本管理器设置，然后完全退出并重新打开 app。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划可以让你在 Copilot 编写代码前审查实现方案。由于你从议题开始，Copilot 已经获得了功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并将计划与议题验收标准进行比较。确认计划涵盖类别和发行方筛选、无障碍控件、数据访问更改和测试。讨论任何不明确的行为，例如多个类别如何组合，或没有匹配游戏时应显示什么。

计划应包括使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。范围应聚焦于实现并测试筛选功能；质量工作流完成后再创建 PR。批准前，要求修改计划中与你的决定不符的部分，并记录议题 URL 及商定的澄清内容，以便稍后验证。

## 明确批准 Autopilot

确认计划符合预期后，选择 **Approve and implement this plan**，或当前版本中的等效选项。不要假定批准后会自动切换模式，请确认活动模式指示器显示 **Autopilot**。

Copilot 会开始实现！你会看到它按照既定计划迭代、生成代码并运行测试。

> [!NOTE]
> 批准计划后，实现可能会立即开始，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止你启动的服务器。

## 审查并验证实现

与其他代码一样，生成的代码也必须在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 根据议题和已批准的澄清内容检查结果，包括多个类别和发行方组合。确认更改遵循现有仓库说明。
3. 检查 lint、单元测试、E2E 测试和类型检查的结果。被跳过的检查不能算通过。
4. 解决失败项并重新运行受影响的检查，然后再接受实现。Playwright 的 E2E 配置会构建并运行预览服务器，也可能复用本地服务器；确认测试使用的是当前工作树的服务器，而不是上一课遗留的服务器。

## 试用新功能

代码看起来不错，但能正常运行吗？像之前一样启动 app，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动 app 并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 片刻之后，app 会启动，Copilot app 中会打开浏览器窗口。
3. 选择一个类别，确认结果与之匹配。清除筛选，再选择一个发行方并确认结果正确。
4. 组合类别和发行方筛选，并根据议题和已批准的计划比较结果。如果支持多个类别，还要验证已商定的组合行为。
5. 尝试没有匹配游戏的筛选组合并检查空状态。清除或重置筛选，确认完整列表会重新显示。
6. 完成后，使用以下提示让 Copilot 停止此会话启动的开发服务器：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 保留此会话以供后续课程使用

现在不要创建或合并筛选 PR。保留此会话、工作树和分支，用于第 4 至第 8 课。接下来会将自定义说明应用于筛选代码，然后添加技能和 QA 改进，最后在第 8 课中创建并合并组合 PR。停止开发服务器后，可以让会话保持空闲；下一课会继续使用同一会话。

## 总结和后续步骤

你使用不同的智能体模式构建并审查了功能。本课中，你：

- 从 GitHub 议题开始新的智能体会话。
- 在 **Plan** 模式中确定需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查了代码。
- 在浏览器画布中手动验证了功能。
