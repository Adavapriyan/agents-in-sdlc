GitHub Copilot をエージェント モードにすると、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。この作業はマシン上でリアルタイムに行われます。VS Code の Copilot Chat では、すべてのツール呼び出しやファイル編集を確認できます。差分をインラインでレビューして個別の変更を承認または却下し、エディターを離れずに追加のプロンプトを送信して作業を改善したり広げたりできます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッション中にエージェントへ指示を出し、ハイ コントラストに加えてライト モードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいという依頼がありました。新しい会話を最初から始める代わりに、既存のセッションに指示して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集など、各ステップを確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの操作を確認します。ファイルの読み込みや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントにもう一度試させます。
4. チャットの上部にある **Files changed** を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツール呼び出しの許可を求められた場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、問題のないコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードを実装するまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライト モードの追加を依頼する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは直前の作業から得たコンテキスト、つまり変更したコンポーネント、スタイルの方針、local storage の使い方を保持しています。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードを追加する提案をします。
3. ハイ コントラスト モードと同じように、新しい編集を確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (例: 切り替え UI のリファクタリングを望まない場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足プロンプトを送信します。

> [!TIP]
> 作業中のセッションに指示を出す方が、最初からやり直すよりも速く進みます。フォローアップ プロンプトで、調整を依頼できます ("CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う")、方向を修正できます ("3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを追加する")、または範囲を広げられます ("両方の切り替えにキーボード ショートカットも追加する")。

## 作業ファイルをレビューする

作業をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧をレビューします。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが案内したアクセシビリティ パターン、つまり ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、進行中のセッションを監視して指示しました。ファイル編集を確認して承認または却下し、コンテキストを保ったままフォローアップ プロンプトを送信して作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または却下しました。
- 作業中のセッションに追加のプロンプトを送り、エージェントを誘導しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが行った変更をレビューします。
